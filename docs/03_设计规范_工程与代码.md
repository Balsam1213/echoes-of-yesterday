# 03 设计规范:工程与代码

> 版本 v1.0 | 状态:定稿 | 日期 2026-11-04

## 1. 工程目录规范

```
EchoesOfYesterday/
├── project.godot                 # M0 由 Godot 生成;视口 640×360、输入映射在此配置
├── scenes/
│   ├── main/                     # 入口场景(Demo 阶段可为空,主场景直指 Level_01)
│   ├── player/                   # Player.tscn
│   ├── echo/                     # Echo.tscn
│   ├── levels/                   # Level_01.tscn 等关卡主场景
│   ├── mechanisms/               # PressureSwitch.tscn、SecurityDoor.tscn、TimeRecorderDevice.tscn、ExitArea.tscn
│   ├── ui/                       # UI.tscn(HUD+暂停+通关)
│   └── dev/                      # 临时开发/验证场景(不上线,M5 前可清)
├── scripts/                      # 与 scenes 同构,按模块分目录
│   ├── player/  echo/  recording/  interaction/  level/  save/
├── tools/                        # 开发期构建/验证脚本(extends SceneTree,headless 运行,如占位素材生成与房间构建)
├── assets/
│   ├── characters/ environment/ mechanisms/ ui/ audio/ effects/
├── data/
│   ├── levels/                   # 关卡配置(预留,JSON)
│   └── settings/
```
- 规则:场景与脚本**同目录同构**;`scenes/dev/` 中的验证场景必须以 `dev_` 前缀命名;禁止在根目录堆放脚本。

## 2. 命名规范

| 对象 | 规则 | 示例 |
| --- | --- | --- |
| 脚本文件 | snake_case + `.gd` | `player_controller.gd` |
| 场景文件 | PascalCase + `.tscn` | `Level_01.tscn` |
| GDScript 类(class_name) | PascalCase | `EchoRecording` |
| 节点名 | PascalCase | `PressureSwitch` |
| 变量/函数 | snake_case;私有加 `_` 前缀 | `frame_index`、`_stop_recording()` |
| 常量/枚举值 | CONSTANT_CASE | `MAX_RECORD_SECONDS` |
| 信号 | snake_case,完成态用过去式 | `switch_activated`、`recording_stopped` |
| 输入 action | snake_case 小写 | `record_toggle` |
| 素材文件 | `主体_状态_序号` snake_case | `player_idle_0.png`、`sfx_switch_on.wav` |

## 3. GDScript 风格规范

1. **缩进**:Tab(Godot 默认);每行一条语句。
2. **类型标注**:函数参数与返回值**必须**标注类型;成员变量尽量标注(`var frame_index: int = 0`)。
3. **文件内声明顺序**(与 Godot 官方风格一致):
   `@tool` → `class_name` → `extends` → `## 文档注释` → 信号 → 枚举 → 常量 → `@export` → public 变量 → private 变量 → `@onready` → `_init/_ready` → `_physics_process` → `_process` → public 方法 → private 方法。
4. **节点引用**:一律 `@onready var switch: PressureSwitch = %PressureSwitch`(配合「作为唯一名称」),禁止硬编码长路径 `$../Level/Room1/...`。
5. **通信方向**:子节点发信号、父节点连接处理(信号向上);跨场景用 `GameEvents` 总线;禁止反向依赖子节点内部实现。
6. **动画状态**:角色动画状态集合固定为 `idle / walk / interact`(记录字段 `anim` 的合法值),新增状态须先改 02 §5.2。
7. **注释密度**:每个脚本头部 `##` 说明职责;公开函数一句话说明;不写"显而易见注释"。
8. **禁止**:魔法数字(提为常量或 `@export`)、在 `_physics_process` 里实例化场景(生成回声等操作移到输入回调)、`get_node` 字符串路径硬编码。
9. **等距贴图偏移**:立起物贴图上移使脚印对齐节点原点时,一律用 `Sprite2D.offset`,**禁止**烘进 `position`——`position` 是 Y-sort 与逻辑的唯一锚点,偏移进 position 会导致排序点错位(墙"躺倒"穿模)。

## 4. 碰撞与分组规范

- 碰撞层定义以 02 §4 为唯一权威(1 world / 2 player / 3 echo / 4 trigger);在 project.godot 中**给层命名**,禁止使用未命名层号。
- 强制分组:所有机关加入 `mechanism` 组;所有可触发机关的实体(玩家、回声)加入 `echo_trigger` 组;回声加入 `echo` 组。重置逻辑依赖分组(02 §8.2)。

## 5. 输入映射规范(FR-015)

所有按键在 `project.godot` Input Map 中配置,action 名称固定如下,**代码中只允许引用 action 名**:

| action | 默认按键 | 功能 |
| --- | --- | --- |
| `move_up` / `move_down` / `move_left` / `move_right` | W / S / A / D | 移动 |
| `interact` | E | 交互 |
| `record_toggle` | R | 开始/结束记录 |
| `play_echo` | Space | 播放记录生成回声 |
| `reset_room` | Backspace | 重置当前房间 |
| `delete_echo` | X | 删除最新回声 |
| `pause` | Esc | 暂停 |

## 6. Git 规范

### 6.1 分支模型
| 分支 | 用途 | 规则 |
| --- | --- | --- |
| `main` | 稳定可玩 | 仅接受 dev 合入;合并点必须可运行 |
| `dev` | 日常开发集成 | 功能分支的合入目标 |
| `feature/<主题>` | 单任务分支 | 如 `feature/time-recorder`;完成后合入 dev 并删除 |

- Demo 体量小,单人开发时允许直接在 `dev` 上小步提交;涉及核心系统(记录/回声)改动建议开 feature 分支。

### 6.2 提交信息
- 格式:`类型(范围): 中文描述`,类型 ∈ `feat / fix / docs / refactor / test / chore`。
- 示例:`feat(echo): 实现逐物理帧回放与末帧停留`、`fix(door): 修复门洞内有实体时仍强制关闭`。
- 频率:**每完成 06 中一个任务(T-x.x)至少一次提交**;里程碑完成时打 tag:`demo-v0.1`(M5)。

### 6.3 提交内容纪律
- `.godot/`、导出产物一律不入库(见根 `.gitignore`);素材源文件(.ase 等)与导出 png 一并入库。

## 7. 版本号约定(Demo 阶段)
- 里程碑对应:`demo-v0.0` 项目启动 → `demo-v0.1` 第一关 Demo 完成(M5)。
- 版本号只写进 `logs/changelog.md` 与 git tag,不在代码内维护。

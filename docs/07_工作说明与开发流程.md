# 07 工作说明与开发流程

> 版本 v1.0 | 状态:定稿 | 日期 2026-11-04

## 1. 角色与职责

| 角色 | 职责 |
| --- | --- |
| 开发者(人类) | 决策、验收、玩测;对提交与文档最终负责 |
| AI 助手 | 按文档执行编码任务、生成素材规格说明、跑测试清单、维护文档一致性;产出必须经人工自测 |
| 测试者(可兼任) | 按 08 清单独立通关验收(NFR-06) |

## 2. 标准开发循环(每个任务 T-x.x)

```
领取任务(06) → 读相关文档章节 → 开发 → 自测(08 对应用例)
→ 更新 logs(devlog 必写) → git commit(03 §6.2) → 在 06 勾选任务状态
```

**一条纪律:任务未自测通过不提交;提交信息必须能对应到任务编号或缺陷 ID。**

## 3. 开发会话协议

### 3.1 开工(每次坐下来开发前)
1. 读 `logs/devlog.md` 最新 1—2 条,恢复上下文;
2. 查 `logs/issues.md` 是否有未关闭的 S1/S2 阻塞当前任务;
3. 从 06 找到下一个未完成任务,明确其 DoD。

### 3.2 收工(每次结束前)
1. 写 devlog:完成项 / 问题与决定 / 下一步(格式见 devlog 文件头);
2. 产生用户可感知变化 → 更新 `logs/changelog.md`;
3. 发现未修缺陷 → 登记 `logs/issues.md`(哪怕不修,先记录);
4. `git add -A && git commit`(工作区不携带未提交改动过夜)。

## 4. AI 协作规范

- **派活模板**:「实现 T3.2。依据:docs/02 §6(回声系统)、docs/03(代码规范)。DoD 见 docs/06 M3。完成后跑 TC-11/12 自测并输出结果。」——引用文档编号,不靠口头转述。
- AI 产出的代码必须:符合 03 风格规范;不越出当前任务范围;附带自测说明。
- AI 修改涉及需求/方案时,必须同步提出文档变更(00 §2.3 联动规则),由人确认后落文档再落代码。

## 5. 缺陷处理流程

```
发现 → 登记 issues.md(ID/严重度/复现步骤) → 排序处理(S1>S2>S3>S4)
→ 修复 → 按 08 对应用例回归 → 填写结论与关联提交 → 关闭
```
严重度定义见 issues.md 文件头。S1(阻断)出现时暂停新任务,先修。

## 6. 需求与方案变更流程

1. 提出变更(为什么改、影响哪些 FR);
2. 更新 01(需求)→ 按联动规则刷新 02/05/06/08;
3. 在 00「偏离登记表」登记对上位文档的任何偏离;
4. `logs/changelog.md` 记一笔;Git 提交信息用 `docs:` 前缀。

## 7. 环境准备清单(M0/T0.1 一次性)

| 步骤 | 内容 |
| --- | --- |
| 1 | 官网下载 Godot 4.3+(标准版,非 .NET 版,本工程纯 GDScript) |
| 2 | VS Code 安装扩展 `godot-tools`;Godot 编辑器设置外部编辑器指向 VS Code |
| 3 | `git config user.name / user.email` 确认;仓库已初始化(main 分支) |
| 4 | 打开 Godot 导入 `EchoesOfYesterday/` 工程(首次为新建,见 T0.2) |

## 8. 每日节奏建议(7 天 Demo 期)

| 时段 | 内容 |
| --- | --- |
| 开工 10 分钟 | 会话协议 3.1 |
| 主开发块 | 按 06 任务推进,任务粒度内小步提交 |
| 收工 15 分钟 | 自测 + 三份日志 + 提交 |

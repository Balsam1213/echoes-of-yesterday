## 2. 总体架构

### 2.1 工程配置
- 视口:640×360;窗口覆盖 1280×720;`stretch/mode=canvas_items`、`aspect=keep`(NFR-05)。
- 主场景:直接指向 `res://scenes/levels/Level_01.tscn`(Demo 无主菜单,D-01)。
- 物理帧率:默认 60 Hz,**记录与回放全部在 `_physics_process` 中驱动**(NFR-02 的根基)。

### 2.2 Autoload 单例(仅 2 个,刻意保持最少)

| 单例 | 职责 |
| --- | --- |
| `GameEvents` | 全局信号总线:`level_completed(level_id)`、`echo_spawned(echo_id)`、`echo_deleted(echo_id)`、`recording_started/stopped` 等。跨场景通信一律走它,避免节点互引用 |
| `SaveManager` | 读写 `user://save.json`:{`unlocked_levels: [1]`、`settings: {}}`;提供 `mark_level_completed(id)`、`is_level_unlocked(id)` |

其余逻辑全部内聚在场景内,由关卡场景组装。

## 3. 2.5D 等距实现

| 项 | 决定 |
| --- | --- |
| TileMapLayer | `tile_shape = Isometric`,基准格 **64×32**,每个 tile 锚点为菱形底部中心 |
| Y-sort | 关卡根节点与实体层均开启 `y_sort_enabled`;角色/机关原点必须落在脚底 |
| 层级组织 | `Level_01(Node2D, y_sort)` 下分:`TileGround`(地板,不参与 y-sort)、`YSorted(Node2D, y_sort)`(墙、门、开关、角色、回声)、`Areas`(出口等纯触发区) |
| 移动方式 | 屏幕空间八向自由移动(W=屏幕上方),不做格子吸附;机关判定靠 Area2D,与摆放网格对齐即可,不约束移动 |
| 摄像机 | Camera2D 跟随玩家(位置平滑),`limit_*` 夹在房间边界内 |

## 4. 碰撞层规划(全项目统一,03 §4 引用)

| 层 | 名称 | 成员 | mask 说明 |
| --- | --- | --- | --- |
| 1 | world | 墙体、门体、场景静态碰撞 | — |
| 2 | player | 玩家 | mask=1(撞墙,不与回声互撞) |
| 3 | echo | 回声 | mask=1(撞墙,不与玩家互撞) |
| 4 | trigger | 压力开关/出口/门洞检测等 Area | mask=2+3(同时识别玩家与回声) |

> 设计决定:**玩家与回声互不阻挡**(不同层且互不 mask)。回声是"过去的影像",卡位会带来强烈挫败感;且回放位置由记录数据直接驱动,物理互撞会破坏复现精度。上位文档未要求互撞,此为明确设计决定。

## 5. 记录系统(TimeRecorder)

### 5.1 采样策略(核心技术决定)
- **每个物理帧(60Hz)采样一条**,在 `_physics_process` 中执行;不记录键盘输入再重放(上位文档明确要求记录实际行为)。
- 上限 30 秒 = **1800 帧**,到达即自动结束记录(FR-005)。
- 内存:单条记录 ≈ 1800 帧 × ~50B ≈ **90 KB**,满足 NFR-01,不需要压缩(demo 不落盘,仅内存持有)。

### 5.2 帧数据结构
```gdscript
# 单帧(Godot Dictionary)
{
    "t": 123,                # 采样序号,从 0 递增
    "pos": Vector2(320,180), # 全局坐标(脚底原点)
    "dir": Vector2(0,1),     # 当前朝向(最后非零移动方向)
    "anim": "walk",          # 动画状态:idle / walk / interact
    "events": []             # 本帧触发的交互事件(字符串数组,如 ["use_e"])
}
```

### 5.3 记录对象与生命周期
```gdscript
class_name EchoRecording
var frames: Array[Dictionary]   # 有序帧数据
var duration: float             # frames.size() / 60.0
```
- R 按下:清空缓冲,开始采样;再次按下或满 1800 帧:结束,打包为 `EchoRecording` 存入关卡管理器(仅保留**最近 1 条**已完成记录,demo 内 Space 播放最近记录;多记录管理为第 3 关需求,接口预留)。
- 重置关卡时:丢弃未完成记录与全部已完成记录。

## 6. 回声系统(EchoController)

- 生成:Space → 以最近已完成记录实例化 `Echo.tscn`,放在记录第 0 帧位置,加入 YSorted 层;通过 `GameEvents.echo_spawned` 广播(HUD 计数)。
- 回放:`_physics_process` 中按 `frame_index` 读取帧,直接赋值 `position`,设置朝向与动画;`frame_index += 1`。
  - 回声**不做物理移动解算**(数据本身来自合法位置);保留 CharacterBody2D 仅为碰撞层标识。
- 播完:停在末帧,`anim="idle"`,保持机关触发能力(第一关规则)。
- 外观:材质改为青蓝色 `#45D9F2`、alpha≈0.6,后续可加扫描线(04 §3)。
- 删除:X 删除**最新**回声(demo 简化;多回声选择器为后续版本);重置时全部清除。
- 上限:3 个;已有 3 个时按 Space 忽略并提示(为 NFR 可扩展性,上限值放 `LevelManager` 配置)。

## 7. 机关系统

### 7.1 信号流
```
PressureSwitch(Area2D, mask=2+3)
  body_entered/exited(且 body 属于 group "echo_trigger") → 计数 ≥1 ? activated : deactivated
    → SecurityDoor.set_open(bool)   # demo 为直连;门内部用计数支持多开关(为第2关预留)
```
- 压力开关与回声均加入 `echo_trigger` 组;Area2D 只认组,不认类型 → 回声天然可触发机关(FR-007)。

### 7.2 安全门防夹规则(FR-004)
- 门内含 `DoorHoleArea`(mask=2+3)。收到"关闭"请求时,若门洞内仍有实体,**保持开启直到清空**再执行关闭;避免玩家在门下被夹。

### 7.3 机关复用约定
- 机关脚本不引用具体关卡;条件组合(多开关与/或)由关卡场景连线或 `LevelManager` 承载。

## 8. 关卡流程与重置(Level_01Manager)

### 8.1 状态机
```
INTRO(出生,显示移动提示) → PLAY(自由探索/记录/回放) → COMPLETE(进入出口,通关文案)
```
- 通关:出口 Area(mask=2,仅玩家)触发 → `GameEvents.level_completed(1)` → SaveManager 写档 → UI 显示通关文案(05 §6),按任意键重玩(重置本关)。
- 教学提示由 LevelManager 按阶段状态置入 HUD(文案见 05 §6)。

### 8.2 重置(Backspace,FR-009)
按序执行,保证无残留:
1. 删除全部 Echo 实例、清空记录缓冲与已完成记录;
2. 压力开关强制 `deactivated`,安全门强制关闭;
3. 玩家瞬移回出生点、朝向/动画复位;
4. UI 回初始提示态。重置通过**遍历场景树分组**(group:`mechanism`/`echo`)实现,不依赖手工点名。

## 9. 存档(FR-014)
- `user://save.json`,字段:{`"unlocked_levels":[1]`, `"settings":{}}`;首次通关时把 1 加入并写盘;启动时读取(demo 仅在 HUD 显示「已解锁:第 1 关」即可)。

# 01 Demo 需求规格说明书

> 版本 v1.0 | 状态:定稿 | 日期 2026-11-04
> 上位文档:《昨日回声_游戏开发方案v1.0.docx》第一、三、八章

## 1. 引言

### 1.1 目的
定义《昨日回声》第一关 Demo(垂直切片)的需求范围与验收基准,作为技术方案(02)、关卡设计(05)、执行计划(06)与测试清单(08)的需求依据。

### 1.2 Demo 定位
第一关「第一次回声」同时承担两个职责:
1. **教学关卡**:让首次接触的玩家无需解释即可理解并完成一次完整的时间回声协作;
2. **技术验证关卡**:验证玩家移动、行动记录、回声回放、机关交互、关卡重置五大核心系统的可靠性,为第 2—8 关复用铺路。

## 2. 范围定义

### 2.1 In Scope(本 Demo 交付)
| 范围项 | 说明 |
| --- | --- |
| Godot 4.x 工程 | 完整可运行的工程,内部分辨率 640×360 |
| 第一关完整流程 | 出生区 → 压力开关 → 安全门 → 出口,含教学提示与通关反馈 |
| 玩家系统 | WASD 八向移动、碰撞、朝向、基础动画(占位素材) |
| 压力开关 + 安全门 | 踩住开启、离开关闭,门具备防夹规则 |
| 时间记录系统 | R 开始/结束,最长 30 秒,记录实际行为数据 |
| 回声系统 | Space 生成回声、逐帧回放、播完停留、上限 3 个、X 删除 |
| 关卡重置 | Backspace 全量复位,无状态残留 |
| 最小 UI | HUD(关卡名/回声数/记录状态与时间轴/键位提示)、暂停菜单、通关界面 |
| 最小存档 | 通关后写入解锁记录(user://save.json) |
| 占位素材 | 色块/几何图形级美术,允许后期替换,但节点结构与规格按最终方案预留 |

### 2.2 Out of Scope(本 Demo 不做)
| 排除项 | 说明 |
| --- | --- |
| 主菜单/设置/关卡选择 | Demo 直接进入第一关(偏离登记 D-01) |
| 第 2—8 关 | 仅要求系统层面预留复用能力,不制作内容 |
| 最终像素美术与音效 | 使用占位素材;音频可为静默,结构预留 |
| 剧情演出、结局 | 仅第一关通关文案 |
| 手柄支持、按键自定义 | 固定键位(见 03 §5) |
| Windows 独立导出包 | 编辑器内运行为准;导出为可选项(M5) |

## 3. 功能需求(FR)

| 编号 | 需求 | 验收要点 | 关联用例(08) |
| --- | --- | --- | --- |
| FR-001 | 玩家八向移动 | WASD 平滑移动,斜向速度归一化,朝向随移动变化 | TC-01 |
| FR-002 | 玩家碰撞 | 不可穿越墙体、门体等静态碰撞物 | TC-02 |
| FR-003 | 压力开关 | 玩家或回声位于触发区域内即激活,全部离开即关闭;有激活/关闭的视听反馈 | TC-03/04 |
| FR-004 | 安全门联动 | 开关激活→门开启可通行;关闭→门阻挡;门洞内有实体时不得夹住实体 | TC-05/06/07 |
| FR-005 | 时间记录 | R 开始记录,再次 R 结束;满 30 秒自动结束;记录位置/朝向/动画状态/交互事件;HUD 显示进度 | TC-08/09/10 |
| FR-006 | 回声生成与回放 | Space 以最近一条已结束记录生成回声;逐帧复现轨迹;青蓝色可辨识;播完停留在末帧 | TC-11/12 |
| FR-007 | 回声触发机关 | 回声可激活压力开关,并可维持激活 | TC-13 |
| FR-008 | 回声管理 | 同时最多 3 个;X 删除最新回声;重复按 Space 可生成多个回声 | TC-16/17 |
| FR-009 | 关卡重置 | Backspace 清除全部回声与未完成记录,机关复位,玩家回出生点 | TC-18/19 |
| FR-010 | 教学提示 | 按关卡阶段显示对应提示文案(见 05 §6) | TC-14 |
| FR-011 | 出口与通关 | 玩家进入出口区域触发通关:显示通关文案,流程结束可重玩 | TC-14/15 |
| FR-012 | HUD | 显示章节关卡名、当前回声数、记录状态与时间进度、键位提示 | TC-08 |
| FR-013 | 暂停菜单 | Esc 暂停:继续/重新开始本关/退出游戏 | TC-21 |
| FR-014 | 最小存档 | 首次通关写入 user://save.json;再次启动时读取并可用 | TC-22 |
| FR-015 | 输入映射 | 所有按键经 Godot Input Map 配置,action 名见 03 §5,禁止硬编码键值 | TC-01 |

## 4. 非功能需求(NFR)

| 编号 | 类别 | 要求 |
| --- | --- | --- |
| NFR-01 | 性能 | 编辑器内稳定 60 FPS;单关同屏实体 ≤ 50;单条记录内存占用 ≤ 1 MB |
| NFR-02 | 回放一致性 | 同一记录多次回放轨迹一致(误差为浮点级);记录数据由固定步长物理帧驱动,不同显示帧率下轨迹一致 |
| NFR-03 | 稳定性 | 重复记录/回放/重置 ≥ 10 次无回声残留、无机关状态错误、无报错 |
| NFR-04 | 可扩展性 | 记录/回声/机关/重置逻辑不得写死第一关内容;关卡相关配置由关卡场景承载(第 2 关可在不改核心代码的情况下搭建) |
| NFR-05 | 画面 | 640×360 内部分辨率,窗口整数倍缩放不模糊(stretch=canvas_items, aspect=keep) |
| NFR-06 | 可用性 | 首次游玩的玩家仅凭游戏内提示即可通关(上位文档最终验收标准) |

## 5. Demo 验收口径

- 功能验收:08 文档「最终验收清单」全部通过;
- 体验验收:一位未参与开发的测试者,不看任何外部说明,5—8 分钟内完成通关;
- 稳定性验收:NFR-03 回归用例通过,全程控制台无 error 级输出。

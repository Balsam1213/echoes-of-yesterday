## 2. 文档管理规范

### 2.1 命名规则
- 文件名:`NN_中文标题.md`,NN 为两位序号;序号确定后不变更,作废文档保留编号并标注状态「已废弃」。

### 2.2 版本与状态
- 状态流转:`草案 → 评审中 → 定稿`;文档头部标注「版本 / 状态 / 日期」。
- 细粒度版本以 Git 提交历史为准;影响需求或方案的重大修订,须同步 `logs/changelog.md`,并在文末「修订记录」追加一行。

### 2.3 变更联动规则(改一处必须检查另一处)
| 修改 | 必须同步检查 |
| --- | --- |
| 01 需求 | 02 技术方案、05 关卡设计、06 执行计划、08 测试清单 |
| 02 技术方案 | 03/04 中受影响的规范、05 的场景脚本拆分、06 的任务与 DoD |
| 05 关卡设计 | 08 对应测试用例 |
| 06 执行计划 | 07 工作说明中的流程引用 |

## 3. 核心术语表

| 术语 | 英文 | 定义 |
| --- | --- | --- |
| 记录 | Recording | 按 R 开始、再次按 R 结束(或满 30 秒自动结束)的一段玩家行为数据,含位置/朝向/动画状态/交互事件序列 |
| 回声 | Echo | 由一条记录生成的角色副本,按原记录逐帧重演行动,最多同时存在 3 个 |
| 回放 | Playback | 回声按记录数据 1 倍速重演的过程 |
| 机关 | Mechanism | 压力开关、安全门等可被玩家或回声触发的场景对象 |
| 重置 | Reset | 按 Backspace 清除回声与未完成记录、机关与玩家回到初始状态 |
| 协作 | Cooperation | 当前玩家与回声同时作用于不同机关以解开谜题的核心玩法 |
| 垂直切片 | Vertical Slice | 第一关 Demo:完整闭环的小体量可玩版本 |
